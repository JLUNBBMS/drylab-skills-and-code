# Security Policy

## Supported versions

Only the latest release is actively maintained.

## Reporting a vulnerability

Do not disclose vulnerabilities publicly if they could lead to:

- API-key exposure
- Bypassing restricted commands or the restricted Python sandbox
- Unconfirmed execution of system commands, file I/O, or network requests
- Sensitive-data exposure through chat history or tool logs

After the repository is public, enable GitHub Security Advisories and submit reports privately through **Security > Report a vulnerability**. Until that channel is configured, the maintainer should provide a dedicated security email address and replace this paragraph.

Include the affected version, reproduction steps, impact, and a suggested remediation. Do not include real API keys or private molecular structures.
